### 3. Coaching Engine (`src/lib/coaching.js`)
**Status:** ✅ Built, tested (59/59 checks pass), **NOT INTEGRATED**

Complete implementation of PROGRAMMING-PRINCIPLES and COACHING-REFERENCE:

**Constants & Data:**
- `PATTERN` — 7 movement patterns (horizontal_push, vertical_push, horizontal_pull, vertical_pull, squat, hinge, carry_core)
- `GOAL` — 5 goals (strength, hypertrophy, fat_loss, conditioning, power)
- `GOAL_PARAMS` — Full goal→parameters table (reps, rest, pairing, progression mechanism)
- `MECHANISM` — 6 progression mechanisms (load_step, total_rep, rest_compression, volume_ramp, density, scheme_rotation)
- `MECHANISM_SPEC` — Advance/reset rules for each mechanism

**Core Functions:**
- `normaliseGoal(input)` — Maps user input to canonical goals (handles aliases: muscle→hypertrophy, cardio→conditioning)
- `paramsForGoal(input)` — Returns reps, rest, pairing, progression for a goal
- `substitute(current, catalog, opts)` — Substitutes exercises by (pattern, equipment, joint_tags), **never crosses patterns**
- `lighterKnobs(goal)` — Returns progression ladder when weight is too light (tempo → unilateral → rest → circuit → reps)
- `balanceCheck(exercises, opts)` — Calculates push/pull ratio, auto-prescribes horizontal_pull when pull < push for 2 weeks
- `backoffTrigger(signals)` — Checks 4 signals: missed sets, joint pain, low readiness, block end
- `applyBackoffWeek(exercises, opts)` — Drops load 10-20%, removes last set, keeps pattern coverage
- `mechanismForGoal(input, opts)` — Chooses progression mechanism, handles equipment limits
- `nextTarget(mechanism, log)` — Progression state machine with advance/hold/reset logic
- `buildWeek(plan)` — Week composer that validates coverage, balance, seeds warm-ups
- `structureForDays(days)` — Maps days available → program structure (3 → full-body, 4 → upper/lower)
- `sessionCoverage(exercises)` / `weekCoverage(sessions)` — Pattern coverage validators

**Imports from programming.js:**
- `PAIRING`, `planIntensity`, `seedWarmup`, `planCircuit`, `CIRCUIT_NOTE`

**Zero imports of coaching.js anywhere in codebase** (verified via grep)

### 4. Programming Logic (`src/lib/programming.js`)

## WHAT'S BROKEN / MISSING

### P0 — CRITICAL (Blocks honest coaching)

#### P0-1: AIWorkoutGenerator bypasses the entire coaching system
**File:** `src/components/ai/AIWorkoutGenerator.jsx`
**Lines:** 25-78 (LLM prompt), 40 (hardcoded days_per_week: 3), 89 (hardcoded difficulty: intermediate)

**Problem:**
The generator sends a bare "you are an expert trainer" prompt to the LLM with **zero connection to:**
- The 41-exercise catalog (`COACHING_EXERCISES` exists in worker, never referenced in prompt)
- The `coaching.js` library (exists, zero imports anywhere)
- Pattern coverage or balance checks (PRINCIPLES §1-2)
- Goal→parameter mapping (REFERENCE §5)
- Warm-up generation (PRINCIPLES §7 calls work-up sets "non-negotiable")
- Substitution logic (PRINCIPLES §6)
- Progression mechanisms (PRINCIPLES §4)

**Consequences:**
1. Exercise names are free text from LLM → won't match `CoachingExercise` slugs → cues/regressions/joint-tags never attach
2. `days_per_week` hard-coded to 3 regardless of client availability (violates PRINCIPLES §3: "onboarding asks days available")
3. `difficulty` hard-coded to `intermediate` (no beginner gating per PRINCIPLES §10)
4. No guarantee of push = pull balance → LLM can ship chest-heavy weeks (violates PRINCIPLES §2: "balance is a hard constraint")
5. No warm-ups generated (PRINCIPLES §7: work-up sets are "mandatory before any heavy lift")
6. Generated plans can't use the substitution engine, progression tracking, or back-off logic

**Fix direction:**
1. Import `coaching.js` into `AIWorkoutGenerator.jsx`
2. For template-matched goals → return template directly from `COACHING_TEMPLATES`
3. For LLM generation → constrain prompt to catalog exercise names, then validate with `buildWeek()` before save
4. Use `paramsForGoal()` to set reps/rest/pairing from goal
5. Use `balanceCheck()` to validate pattern coverage before save
6. Wire in `seedWarmup()` for warm-up generation

#### P0-2: Goal vocabulary mismatch
**File:** `src/components/ai/AIWorkoutGenerator.jsx`
**Lines:** 153-158 (goal dropdown)

**Problem:**
- UI dropdown offers: `strength / muscle / cardio / balanced / fat_loss`
- Coaching system expects: `strength / hypertrophy / fat_loss / conditioning / power` (per REFERENCE §5, PRINCIPLES §8)
- `muscle`, `cardio`, `balanced` have no row in the goal→parameter table

**Mitigation in coaching.js:**
- `normaliseGoal()` maps aliases: `muscle → hypertrophy`, `cardio → conditioning`
- `balanced` is aliased to `hypertrophy` with `mapped: false` warning (needs user confirmation)

**Fix:**
1. Align dropdown to the 5 documented goals, OR
2. Use `normaliseGoal()` to map UI goals to coaching goals and show user the mapping
